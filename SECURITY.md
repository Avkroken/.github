# Security Policy

## Reporting a vulnerability

Do not report security vulnerabilities in public issues.

Use the affected repository's **Security** tab and **Report a vulnerability** flow when available. If private vulnerability reporting is not available for that repository, contact `dev@denied.se`.

Include the affected repository/component, a concise description, reproduction steps when practical, potential impact, and any relevant evidence. Do not include credentials, tokens, private keys, personal data, or other secrets in public issues or pull requests.

## Supported versions

Unless a repository documents a narrower support window, only the latest release and current `main` are supported.

Repository-specific security invariants belong in that repository's own `SECURITY.md` when they are needed; organization-wide merge and agent policy is not duplicated here.
